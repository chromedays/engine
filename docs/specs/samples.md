# 샘플 스펙 (고정된 씬과 로직, 샘플마다 독립 실행 파일)

상태: 합의됨 (2026-11-08). 이 스펙의 변경은 먼저 합의한다.

### 목표

기능 하나를 개발하고 확인할 때 쓰는 작은 프로그램들. 샘플마다 씬과 로직이 C 코드로 고정되어 있고, 실시간으로 돌며, 입력이
필요 없다. 에디터는 없다. 샌드박스(씬 편집과 탐색)와 시각 회귀 테스트(N 프레임 캡처와 비교) 사이의 세 번째 도구다.

| | 샌드박스 | 샘플 | 시각 테스트 |
|---|---|---|---|
| 역할 | 씬 편집과 탐색 | 기능 하나를 실행되는 모습으로 보이고 잰다 | 회귀 잡기 |
| 씬 | 편집할 수 있는 `.nvscene` 파일 | C 코드, 고정 | C 코드, 고정 |
| 입력 | 에디터 전체 | 필요 없음 (카메라 드래그만 된다) | 없음 |
| 지켜야 할 규칙 | save, undo, search, 문자열, 폰 UI | 없음 | 없음 |

합의된 결정:

- **샘플 하나가 실행 파일 하나다.** `samples/<name>/`에 있고, 타깃 이름이 샘플 이름이다(`stress`). 샘플끼리 코드를 나누지 않는다:
  공유 셸, 샘플 표, 샘플 고르기가 없다.
- 샘플은 **엔진에만** 의존한다. `sandbox/`도 다른 샘플도 include하거나 링크하지 않는다. 두 샘플이 같은 코드를 필요로 하면, 그때
  그 코드를 엔진으로 옮길지 정한다(코딩 표준: 두 번째로 필요할 때 뽑는다). 지금은 카메라 입력, 프레임 통계, 벤치마크가 stress 안에 있다.
- **입력이 필요 없다.** 슬라이더, 버튼, 스크립트(`--script`, Windows의 `call` 표), 명령줄 옵션이 없다. 샘플은 시작하자마자 스스로
  할 일을 한다. 뷰포트 드래그로 카메라를 돌리는 것만 된다.
- **디버그 export는 읽기만 한다**(Debug 빌드, `Module._<name>_debug_*`): 테스트가 끝나기를 기다리고 결과를 확인하는 데 쓴다.
  값을 바꾸는 export는 없다.
- 웹, Windows, Linux가 모두 빌드한다(`NV_BUILD_SAMPLES`, 최상위 프로젝트일 때만 켜짐). 웹은 `<prefix>/<name>/`에 설치된다.
- 샘플은 그 샘플이 읽는 에셋만 담는다(`nv_setup_executable`의 `PRELOAD`).
- UI 문자열은 영어이고 `T()`를 거치지 않는다.
- 서드파티: 없음.

### 첫 샘플: stress

샌드박스의 스트레스 씬(`stress.md`)을 옮겼다. 샌드박스에서는 그 씬, 워크로드 동작 넷, 생성기, `palette`와 `benchmark` 블록,
Stress 탭, 벤치마크, 그 디버그 export와 스크립트 명령을 지웠다(`scene_file.md`의 2026-11-08 메모).

```
samples/stress/
  CMakeLists.txt   타깃 stress: nv에만 링크. assets/fonts와 assets/quaternius만 담는다
  stress.h         상태(Stress), 워크로드(Workloads, WorkloadSettings), 프레임 시간, 벤치마크
  main.c           셸: 창, 프레임, 카메라, 패널(벤치마크와 통계), 스스로 도는 벤치마크, 읽기 전용 디버그 export
  workloads.c      씬, 워크로드(그리드, 체인, 군중, 이펙트, 뼈), 이펙트 정의, 벤치마크 단계 표
```

- **씬:** `stress.nvscene`과 같다. 카메라 (fov 50°, yaw 0.45, pitch 0.42, 거리 28), 태양, 바닥, 팔레트 (바탕과 색상환 199색),
  주변광 0.15. 렌더러는 샌드박스의 처음 설정으로 고정한다(그림자 2048 / 터치 1024, MSAA 4x, PBR Neutral, 블룸 0.04, 해상도 1/1 /
  터치 1/2).
- **벤치마크:** 시작하자마자 단계를 차례로 돈다. 단계마다 워크로드를 비우고(`stress_reset`) 그 단계의 설정만 켜며, 1초 준비 뒤
  3초를 잰다. 마지막 단계가 끝나면 결과 표를 로그에 쓰고(`nv_log`, 출처 `stress`) 처음부터 다시 돈다. 패널은 지금 단계와, 마지막으로
  끝난 한 바퀴의 표(첫 바퀴 동안은 그때까지의 표)를 보인다.
- **단계 (22):** Cubes 250 / 1000 / 4000 / 8000 / 16000, Colors 199 (큐브 4000), Churn 256 (큐브 4000), Chain 1000, Crowd 8 / 32 /
  60 / 120 / 200, Bones 200, Particles 250k / 1M / 2M, Explosions 200, Missiles 500 / 2000, Beams 500, Decals 2000.
- **시간:** 워크로드, 애니메이션, 이펙트는 매 프레임 고정 dt(1/60 s)만큼 나아간다. 프레임 시간은 실제로 잰다.
- **노드 예산:** 군중, 체인, 그리드 순서로 남은 노드와 애니메이터 안에서 나누고, 줄이는 것을 늘리는 것보다 먼저 한다. 캐릭터는
  만들면 남는다(애니메이터는 지울 수 없다). 그래서 두 번째 바퀴부터 Cubes 16000은 캐릭터 200명의 노드만큼 적게 만든다.

### 디버그 export (stress, Debug 빌드)

| export | 값 |
|---|---|
| `stress_debug_stat(which)` | 0 그린 프레임, 1 노드, 2 그리기, 3 살아 있는 파티클, 4 로그의 경고와 오류 수 |
| `stress_debug_built(which)` | 0 큐브, 1 고리, 2 보이는 캐릭터 |
| `stress_debug_benchmark(which)` | 0 끝난 바퀴, 1 지금 단계, 2 단계 수, 3 마지막 바퀴가 잰 프레임 합 |

### 확인

- 웹 Debug를 헤드리스 Chromium(SwiftShader)에서, 입력 없이: 한 바퀴 22단계가 끝나고, 각 단계가 요청한 것을 만들고, 로그에 경고와
  오류가 없다. SwiftShader의 시간은 의미가 없다.
- 샌드박스: 씬 두 개(쇼케이스, 체스), Play/Stop 뒤 CRC가 같고, save 왕복과 새로고침이 된다. 스트레스 씬이 있던 옛 저장도 열린다
  (모르는 씬의 `SCNE`는 건너뛴다; `SAVE_VERSION`은 그대로).
- Linux 빌드와 Windows 빌드는 push 전에 확인한다.
