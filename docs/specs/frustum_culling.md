# 프러스텀 컬링 스펙

상태: 초안 (2026-11-08). 합의 전이다. 이 스펙의 변경은 먼저 합의한다.

### 목표

씬 패스가 카메라 프러스텀 밖의 메시 노드를 그리지 않는다. 섀도 패스의 caster 컬링도 같은 검사로 바꾼다. 둘 다 CPU가 드로우 콜을
기록하기 전에 건너뛰는 것이다: 건너뛴 노드는 드로우 콜도, 정점 셰이딩(스키닝 포함)도, 클리핑도 없다.

이것은 LOD(Level of Detail)의 앞 단계다. LOD 선택은 같은 노드별 바운드와 같은 카메라 데이터를 쓴다(LOD는 별도 스펙).

범위 밖:

- 오클루전 컬링(Hi-Z 등), GPU에서 하는 컬링(indirect draw), 인스턴싱.
- 공간 계층(BVH, 그리드). 노드는 최대 16384개이고 검사는 노드마다 상수 비용이라 선형으로 돈다. 측정에서 이 루프가 눈에 띄면 따로 정한다.
- 작은 객체 컬링(화면에서 몇 픽셀보다 작은 노드 빼기). LOD와 함께 정한다.
- 오브젝트 버퍼 업로드 줄이기. 두 패스가 같은 슬롯을 쓰므로 지금처럼 전부 올린다.
- 이펙트(`vfx.c`)는 GPU에서 이미 자기 컬링을 한다. 데칼, 디버그 라인, 피킹은 바뀌지 않는다.

### 지금 (2026-11-08)

- **씬 패스:** 컬링이 없다. 수집 루프(`engine/renderer.c`, `nv_renderer_draw`)가 메시 노드를 전부 `objects`에 넣고, 씬 패스가 그
  전부를 그린다. `NvRenderStats.draws`는 메시 노드 수와 같다.
- **섀도 패스:** caster 컬링이 있다(`shadows.md`, 2단계). 캐스터마다 포즈 박스(`nv_renderer_mesh_bounds`)를
  `light_view_proj × world`로 변환해 그 AABB(Axis-Aligned Bounding Box)를 라이트 클립 공간의 단위 상자와 비교한다. 다섯 면만
  보고 near 면(`box.max.z < 0`)은 보지 않는다. 라이트가 정사영이라 w가 1이어서 맞는 방법이다.
- **평면 추출:** `engine/vfx.c`의 `frustum_planes`가 행렬에서 평면 6개를 뽑아(정규화, 안쪽 방향) 파티클 컬링 셰이더에 넘긴다.
  `internal`이라 렌더러가 쓰지 못한다.

### 접근법

| 방법 | 원근 프러스텀 | 정사영 라이트 상자 | 꼭 맞음 | 판단 |
|---|---|---|---|---|
| A. 박스를 클립 공간으로 변환해 min/max 비교 (지금 섀도 패스) | **틀린다.** w로 나눠야 하고, w = 0을 가로지르는 박스는 꼭짓점의 투영이 실제 모양을 보여주지 못한다(카메라 뒤 꼭짓점은 부호가 뒤집힌다). 화면에 있는 객체가 컬링될 수 있다 | 맞다 (w = 1) | 회전한 박스를 감싼 AABB라 헐렁하다 | 원근에 못 쓴다 |
| B. 바운딩 스피어 대 평면 6개 | 맞다 | 맞다 | 길거나 납작한 객체(캐릭터, 바닥)에 헐렁하다 | LOD 크기에만 쓴다 |
| **C. 노드 로컬 박스 대 로컬 공간 평면 6개** | 맞다 | 맞다 | 박스 자체로 검사한다(감싼 AABB를 만들지 않는다) | **이것을 쓴다** |

C가 원근과 정사영에 모두 맞는 까닭: 나눗셈 전의 클립 공간에서 프러스텀은 선형 부등식(`-w ≤ x ≤ w`, `-w ≤ y ≤ w`, `0 ≤ z ≤ w`)이고,
부등식 하나가 동차 공간의 평면 하나다. 나누지 않으므로 w = 0이나 w < 0도 그냥 숫자다. 리버스 Z의 `view_proj`도 깊이가 `0 ≤ z ≤ w`
범위라서 같은 추출이 맞다(이펙트가 이미 그 행렬로 쓴다).

검사: 평면 `(n, d)`에 대해 박스(중심 `c`, 반 크기 `h`)가 밖에 있는 것은 `dot(n, c) + dot(|n|, h) + d < 0`일 때다. 평면 하나가 그러면
노드를 건너뛴다. 이 검사는 보수적이다: 프러스텀 모서리 근처에서는 밖의 박스가 안으로 판정될 수 있지만(그리기만 할 뿐 틀리지 않는다),
보이는 박스가 밖으로 판정되는 일은 없다.

### 정한 것 (제안)

| 주제 | 제안 |
|---|---|
| 바운드 | 노드마다 포즈가 적용된 **로컬** 박스(`nv_renderer_mesh_bounds`)를 수집 루프에서 프레임당 한 번 계산해 객체 슬롯마다 둔다. 두 패스가 이것을 쓴다. 월드 AABB로 저장하지 않는다: 다시 변환하면 AABB가 두 번 커진다 |
| 평면 | 프레임마다 카메라 평면 6개와 라이트 평면 6개를 한 번 뽑는다. 노드마다 `p_local = Mᵀ p_world`(M = `node->world`)로 로컬 공간에 옮긴다. 역행렬이 필요 없고(스케일 0인 노드도 된다), 노드당 곱셈 96번이다 |
| 씬 패스 | 카메라 `view_proj`의 평면으로 검사해 보이는 객체 목록을 만들고, 씬 패스는 그 목록만 그린다. `first_instance`는 객체 슬롯 그대로라서 셰이더의 `instance_index`는 바뀌지 않는다. 그리는 순서도 슬롯 순서 그대로다 |
| 섀도 패스 | 지금의 클립 공간 AABB 검사를 같은 함수(라이트 `light_view_proj`의 평면)로 바꾼다. near 면이 더해진다. 섀도 파이프라인에는 depth clamp가 없어서 near 면 밖의 캐스터는 지금도 GPU에서 잘린다: 그림은 바뀌지 않는다 |
| 빈 박스 | 정점이 없는 메시의 빈 박스는 그리지 않는다 |
| 켜고 끄기 | `NvRenderer.culling`(b32). 앱이 정한다. 샌드박스는 View 탭의 체크박스로 정하고 기본은 켜짐이다. 끄면 지금과 같다(섀도 caster 컬링은 늘 켜져 있다: 지금 동작) |
| 통계 | `NvRenderStats.draws`는 씬 패스의 드로우 콜 수가 된다. `culled`(씬 패스에서 뺀 노드)와 `shadow_culled`를 더한다. `triangles`는 그린 것만 센다 |
| 의존성 | 없다. 서드파티 라이브러리를 쓰지 않는다 |

### 엔진 변경

- `engine/math.h`: `NvFrustum { f32 planes[6][4]; }`, `nv_frustum_from_matrix(NvMat4 m)`(`vfx.c`의 `frustum_planes`를 옮긴 것; 정규화,
  안쪽 방향), `nv_frustum_to_local(const NvFrustum* world, NvMat4 m)`, `nv_box_outside_frustum(NvBox box, const NvFrustum* f)`.
  GPU가 필요 없어서 Node와 네이티브 테스트가 그대로 부른다. `vfx.c`는 옮긴 함수를 쓴다.
- `engine/renderer.h`: `NvRenderer.culling`, `NvRenderStats.culled`, `NvRenderStats.shadow_culled`. 내부 배열 `object_boxes`
  (`[NV_MAX_NODES]`, 아레나)와 `visible`(보이는 객체 슬롯 목록).
- `engine/renderer.c`: 수집 루프가 `object_boxes[i]`를 채우고 카메라 프러스텀으로 `visible`을 만든다. 섀도 패스는 `object_boxes`와
  라이트 프러스텀으로 검사한다(지금의 `nv_renderer_mesh_bounds` 호출과 클립 공간 비교가 빠진다). 씬 패스는 `visible`만 돈다.
- `engine/gpu.h`와 두 백엔드는 바뀌지 않는다. 셰이더도 바뀌지 않는다.

이 API는 엔진 쪽이라 다른 앱(오토배틀러)도 따라온다: `culling`을 켜지 않으면 지금과 같다. (zero가 기본이므로 앱이 켜야 한다.
기본을 켜짐으로 할지는 열린 질문.)

### 샌드박스 변경

- **View 탭:** "Culling" 섹션에 "Frustum culling" 체크박스. `search_row`로 써서 검색과 팔레트에 나온다. 한국어 행은 `sandbox/strings.c`.
- **저장:** 새 태그 `CULL`(`sandbox/save.c`, 0 꺼짐, 1 켜짐). 태그가 없는 옛 저장은 켜짐으로 읽는다. 기존 태그의 뜻은 바뀌지 않으므로
  `SAVE_VERSION`은 그대로다. `save.md`의 표에 행을 더한다. 저장되므로 undo가 따로 코드 없이 된다.
- **Stress 탭:** 통계에 "Culled", "Shadow culled" 행. 벤치마크는 측정할 때의 컬링 상태를 MSAA처럼 기록한다(`Benchmark.culling`).
- **디버그 export**(웹 `NV_DEBUG_EXPORT`, Windows `sandbox_debug_calls`의 행): `_sandbox_debug_render_stats(k)`(k: draws, culled,
  shadow_draws, shadow_culled, triangles)와 `_sandbox_debug_set_culling(on)`.

### 측정

스트레스 씬의 기본 시점은 그리드를 거의 다 본다. 그래서 기본 시점만 재면 컬링 효과가 거의 안 보인다. 시점 세 개로 잰다:

| 시점 | 뜻 |
|---|---|
| 기본 | 거의 다 보인다: 검사 비용만 더해지는 최악의 경우 |
| 가까이 | 그리드 가운데에 다가가 일부만 보인다 |
| 반대쪽 | 그리드를 등진다: 거의 다 컬링된다 |

시점마다 컬링 끄기/켜기로 `Frame`, `CPU draw`, `Draws`, `Culled`, `Shadow draws`, GPU 씬·섀도 시간(`timestamp-query`가 있을 때)을
적는다. 웹 Release는 헤드리스(SwiftShader: 시간은 참고만, 개수는 정확)와 사용자의 Chrome으로 잰다. 결과는 "찾은 것"에 표로 적는다.

### 위험

| 위험 | 대응 |
|---|---|
| 바운드가 실제보다 작아서 보이는 노드가 사라진다(화면 가장자리에서 깜빡임) | 정점 셰이더가 정점을 옮기는 것은 스키닝뿐이고, 스키닝은 조인트 박스로 감싼다. 시각 회귀 테스트와 아래 스크린숏 비교가 잡는다 |
| 검사 비용이 아끼는 것보다 크다(다 보이는 시점) | 노드당 곱셈 약 100번. 측정의 "기본" 시점이 답한다 |
| 그림자가 꺼져 있을 때 스키닝 포즈 박스 계산이 새로 생긴다 | 지금은 섀도 패스에서만 계산한다. 조인트 박스는 최대 4096개다. 측정한다 |
| 섀도 caster 검사가 바뀌어 그림자가 바뀐다 | near 면 하나가 더해질 뿐이고, 그 캐스터는 지금도 GPU에서 잘린다. 스크린숏 비교 |

### 검증

- **새 테스트** `tests/culling_test.c`(ctest; 웹은 Node, Windows와 Linux는 네이티브):
  - 안쪽 박스, 평면 6개 각각의 바깥 박스.
  - 카메라 옆에서 앞뒤로 길게 뻗어 w = 0을 가로지르는 박스: 보여야 한다(방법 A는 이것을 틀린다).
  - 카메라를 둘러싼 큰 박스(바닥): 보여야 한다.
  - 회전한 얇은 박스가 감싼 AABB로는 프러스텀에 닿지만 박스 자체는 밖인 경우: 컬링된다.
  - 같은 카메라의 리버스 Z 행렬과 표준 행렬이 같은 결과를 낸다.
  - 정사영 라이트 행렬에서 지금의 클립 공간 검사와 결과가 같다(near 면 밖의 박스만 다르다).
- **웹** Release와 Debug(헤드리스 Chromium, 데스크톱과 폰 크기): 세 씬 모두 컬링 끄기/켜기의 스크린숏이 픽셀까지 같다. 반대쪽 시점에서
  `draws`가 0에 가깝다. WebGPU 오류와 로그 오류가 없다. 저장 왕복(`_sandbox_debug_save_round_trip`)과 undo 한 단계.
- **Linux:** `just visual`의 기준 그림이 바뀌지 않는다.
- **Windows** Release와 Debug: 같은 확인을 스크립트(`call _sandbox_debug_set_culling`, `screenshot`)로. `[d3d12]` 메시지가 없다.
  사용자가 한다(`engine/renderer.c`는 플랫폼을 모르는 파일이다).

2. **렌더러:** `object_boxes`, 씬 패스 컬링, 섀도 패스를 같은 검사로, 통계. 샌드박스는 아직 켜기만 한다(UI 없음). 스크린숏 비교.
3. **샌드박스:** View 탭 체크박스, `CULL` 저장, Stress 탭 통계, 벤치마크 기록, 디버그 export, 한국어 행.
4. **측정:** 위 "측정"의 표. "찾은 것"에 적는다.
5. **정리:** AGENTS.md(렌더러 설명, 디버그 export), `stress.md`의 "Today every node is one draw call, nothing is culled" 문장, `shadows.md`의

### 열린 질문

1. **기본값:** 엔진의 `culling`을 zero 기본(꺼짐, 앱이 켬)으로 할까, 렌더러 초기화에서 켜둘까? 제안: 초기화에서 켠다. 끌 이유는
   비교와 디버깅뿐이고, 오토배틀러가 할 일이 없다.
2. **컬링 고정(freeze):** 한 프레임의 프러스텀을 고정하고 카메라를 돌려, 컬링된 노드가 사라지는 것과 고정된 프러스텀(디버그 라인)을 눈으로
   보는 기능. 검증에 쓸모 있다. UI에 넣으면 저장 규칙을 따라야 하는데 고정된 행렬까지 저장하는 것은 어색하다. 제안: 디버그 export만 두고
   UI에는 넣지 않는다.
3. **UI 자리:** View 탭의 새 "Culling" 섹션인가, Stress 탭인가? 제안: View 탭(그림자, 안티에일리어싱과 같은 렌더링 설정).
